### 🔹 Atividade 01 — Utilização de API Express no Front-end

**Descrição:**
Desenvolvimento de uma aplicação utilizando uma **API criada com Express.js** e realizando sua integração com o **Front-end**. A atividade teve como objetivo praticar o consumo de uma API própria, realizando a comunicação entre o Front-end e o Back-end por meio de requisições HTTP.

O projeto foi dividido em dois repositórios: um destinado ao **Front-end**, responsável pela interface e pelo consumo da API, e outro destinado ao **Back-end**, responsável pela criação e disponibilização da API utilizando Express.js.

**Tecnologias:**

* Express.js
* Node.js
* React
* API REST
* Vercel
* Render

### 🔹 Atividade 01 — Gestão do Projeto Integrador (Projetos Front-End)

**Descrição:**
Planejamento e gestão das tarefas do **Projeto Integrador Interdisciplinar** aplicando os conceitos de gestão de projetos Front-End vistos em aula: gestão de requisitos, gestão do backlog, priorização, estimativas, *Definition of Done* e Scrum.

O projeto escolhido foi uma **Catraca com Reconhecimento Facial**, e todo o processo de gestão foi documentado em um arquivo Markdown, utilizando um board Kanban para acompanhar o andamento do projeto.

**O que foi desenvolvido:**
- **Product Backlog** com as funcionalidades do sistema (captura de imagem, treinamento do modelo facial, cadastro de usuários, logs de acesso, dashboard)
- **Prioridades** definidas em Alta, Média e Baixa com base no valor de negócio e dependências técnicas
- **Tarefas e Estimativas** — divisão das histórias em tarefas menores com estimativa de esforço
- **Sprint** — seleção dos itens de maior prioridade para o ciclo atual
- **Quadro Kanban** com as colunas *To Do*, *In Progress*, *Review/Test* e *Done*
- **Estratégia de Branches** — `main`, `develop` e `feature/nome-da-tarefa`
- **Critérios de Conclusão (Definition of Done)** — código implementado, testado, revisado via Pull Request e integrado

**Conceitos aplicados:**
- Gestão de Requisitos (Requisito → User Story → Tarefas)
- Gestão do Backlog
- Gestão de Prioridade e Estimativa
- Definition of Done
- Scrum / Kanban

### 🔹 Atividade 01 — Box Model e Flexbox

**Descrição:**
Criação de um projeto com os arquivos `index.html` e `style.css`, incluindo o CSS de forma **externa** ao HTML através da tag `<link>`. Foram adicionados **20 elementos** com valores atribuídos em todas as propriedades do **Box Model** (Content, Padding, Border e Margin) e utilizadas **20 propriedades de Flexbox** para organizar os elementos de forma responsiva.

**O que foi desenvolvido:**
- CSS externo vinculado com `<link rel="stylesheet" href="style.css">`, sem estilos in-line ou internos
- 20 caixas (`.caixa-1` até `.caixa-20`) com Content (`width`, `height`), Padding, Border e Margin declarados por extenso
- 20 propriedades de Flexbox (`flex-direction`, `justify-content`, `align-items`, `flex-wrap`, `gap`, entre outras)
- Layout responsivo com breakpoints para desktop, tablet e mobile

**Tecnologias:**
- HTML5 / CSS3

**🔗 Links da Atividade:**
- [Pasta no repositório (`atividade-01-boxmodel-flexbox`)](https://github.com/Pedro-Vitor-Ribeiro-Silva/aula-07-FrontEnd/tree/main/atividade-01-boxmodel-flexbox)

### 🔹 Atividade 02 — Tailwind CSS

**Descrição:**
Criação de um projeto utilizando pelo menos **30 classes diferentes do Tailwind CSS**, aplicadas a cores, tipografia, espaçamentos, dimensões, bordas, posicionamento, flexbox, grid e responsividade. A entrega foi documentada em Markdown com prints do código, da aplicação em funcionamento e a lista das classes utilizadas com suas respectivas funções.

**O que foi desenvolvido:**
- Página completa com navbar, hero, cards, comparativo *CSS manual x Tailwind*, formulário e footer
- **189 classes distintas** do Tailwind CSS cobrindo as 9 categorias exigidas, sem nenhuma regra CSS própria
- Layout responsivo com os prefixos `md:` e `lg:` (abordagem Mobile First)
- Tailwind carregado via **Play CDN**

**Tecnologias:**
- HTML5 / Tailwind CSS 4
